# 自建路網圖磚

把用路人回報的路口規則烘進 BRouter 的 rd5 圖磚，好讓回報改變得了路線
（[ADR-0017](../../docs/adr/0017-build-our-own-routing-tiles.md)）。

```bash
python build_tiles.py                                   # 全套，約 5 分鐘（含下載 326 MB）
python build_tiles.py --skip-fetch                      # 已經抓過原始資料
python build_tiles.py --skip-fetch --rules selftest_rules.tsv   # 證明注入會改變路線
```

產出在 `../build/tiles/segments4/`：`E120_N20.rd5` 與 `E120_N25.rd5`，共約 20 MB。

## 為什麼要自己建

BRouter 的 profile 讀的是 OSM 標籤，**讀不到我們的資料庫**。所以用官方圖磚時：

| | 進得了路線計算嗎 |
| --- | --- |
| OSM 既有的轉向限制（全台 2,590 條） | ✅ |
| 騎士回報的禁止左轉 | ❌ |
| 待轉成本 | ❌ |

騎士停在路口按下「禁止左轉」，他的合理期待是下一個人不會被導來這裡。
唯一能做到這件事的位置，是**建圖之前的 OSM 資料本身**。

## 三步，一行 BRouter 的程式都沒改

```
taiwan-latest.osm.pbf ──┐
                        ├─→ OsmInject ─→ taiwan-scooter.osm.pbf ─┐
種子庫的規則 ───────────┘                                        │
                                                                 ▼
                                    OsmFastCutter → PosUnifier → WayLinker → *.rd5
```

後面三步是 BRouter 官方的建圖工具（在 `-all.jar` 裡），原封不動地跑。
**刻意不去包裝或改寫它們** —— BRouter 每隔一陣子會發新版，而「我們改過它的
內部類別」這種相依性，會在升級那天才爆炸。注入全部發生在它們看到資料之前。

`OsmInject` 也不重寫整份 pbf：pbf 是一串各自獨立的 blob，沒動到的原封搬過去，
只有裝了要切的 way 的那幾個 blob 才解開重編，最後補一個裝合成關聯的 blob。
326 MB 跑完兩趟約 8 秒。

## 兩種注入，機制完全不同

**禁止左轉**合成一條 `type=restriction` 關聯（from way / via node / to way）。
這是 OSM 自己的表達方式，BRouter 1.4.8 起原生支援 —— 我們只是多寫了幾筆進去。
乾淨、沒有副作用，而且它是**唯一有合法性問題的那一種**：待轉播錯只是慢一點，
禁止左轉播錯是違規。

**待轉**沒有這麼漂亮的位置，而且**目前是關著的**（要 `--hook-turns` 才會注入）。
機制本身是通的：把左轉的離開臂第一段切成獨立的 way、掛上 `scooter:hook_turn=yes`，
標籤確實進得了 rd5（實測：拿 `costfactor` 擋那條 link，路線會改變）。
**缺的是成本模型** —— 見下面「待轉為什麼還沒生效」。

## 待轉為什麼還沒生效

`scooter-tw.brf` 是從 `car-fast.brf` 改來的，而 car-fast 在檔頭宣告了
`---model:btools.router.KinematicModel`。BRouter 於是走 `KinematicPath`，
**而 `KinematicPath` 整支沒有呼叫過 `getTurncost()`**（`StdPath` 才有；
javap 計數 0 對 1）。實測佐證：`turncost` 設成 2000 跑台北到台中、76 個轉彎，
成本一個位數都沒有變；同一個值放進 `moped.brf`（沒有宣告 model，走 StdPath）
則成本從 7,247 跳到 19,452、路線也換了。

**不能只把 `---model:` 那行刪掉。** car-fast 的 `costfactor` 對一般道路是 **0**
（它是疊在動力學成本上的加碼，不是距離乘數），改走 StdPath 之後距離變成免費 ——
實測路線成本歸零、有一組起訖直接算不出來。要讓待轉成本生效，得連 `costfactor`
一起改寫成距離乘數，那是另一件事，見決策檔案 D10。

順帶一提，就算生效了它也有精度上限，而那是 BRouter 的結構決定的：`turncost`
是 **way 層**的變數（進入那條 link 時求值，再乘上 `1 - cos 轉角`），不是
「從哪來、往哪去」的函數。所以同一段離開臂，**對向來車的右轉會吃到同一筆成本**。
直行不受影響（轉角為零），而直行是大路口最常見的動作 —— 節點層的 `initialcost`
會連直行一起罰，那才是真的錯。

## 切 way 的那條安全規則

**被既有 `type=restriction` 關聯引用到的 way，一律不切**，並且寫進報告。
切開之後那條關聯會指到半條路，BRouter 可能解成反方向的轉向限制 ——
拿一個軟成本去換一條真的禁止左轉出錯，不划算。這條規則會真的擋下東西：
自我測試那兩筆，第一筆選的路口就是這樣被擋掉的。

## 什麼會進圖磚，什麼不會

只有 `status` 是 **OFFICIAL 或 VERIFIED** 的規則會注入。回報一進資料庫是
PENDING，那些不進 —— 一筆錯誤的禁止左轉會讓所有人在那個路口繞遠，
**而且不會有人抱怨**，因為繞遠的路線看起來仍然合法，騎士無從得知它為什麼繞。
ADR-0013 說禁止左轉一律進審核佇列，這裡是那條規定真正的理由。

**目前種子庫裡一條禁止左轉都沒有**（回報通道還沒開），所以正式建圖是空注入。
`selftest_rules.tsv` 就是為了這件事存在的：空注入證明不了管線會動。

## 驗收

`build_tiles.py` 最後會跑 `RouteCheck`，把四組起訖算一遍。挑這四組是因為
它們壞掉的方式不一樣：跨 N25 分界的那組壞掉是「南下算不出路線」，
市區的壞掉是「繞遠」，長程的壞掉是「上了國道」。

自建與官方圖磚的對照（同一份 `scooter-tw.brf`）：

| 起訖 | 自建 | 官方 |
| --- | --- | --- |
| 台北車站 → 市府 | 6,398 m | 6,398 m |
| 信義 → 大直 | 6,667 m | 6,716 m |
| 台北 → 台中 | 182,743 m | 182,742 m |

距離對得上。成本差 1% 左右，來源是**資料日期不同**（Geofabrik 的快照與
brouter.de 的重建不是同一天）與**我們不帶高程**。

跑自我測試時，`台北車站 → 市府` 會從 6,398 變成 6,627 公尺，
**其餘三組一個位元都不變** —— 注入是外科手術式的，不是整體擾動。

## 高程刻意不放

`PosUnifier` 吃一個 SRTM 目錄，我們給它一個不存在的路徑。`scooter-tw.brf` 一個
`uphillcost`／`downhillcost` 都沒有指定，高程只會改變回報的時間與能量，
不會改變路線 —— 上面那張對照表就是證據（自建無高程、官方有高程，距離一樣）。

## 圖磚大小與官方不一樣，那是對的

| | 自建 | 官方 |
| --- | --- | --- |
| `E120_N20.rd5` | 17.5 MB | 22.1 MB |
| `E120_N25.rd5` | 2.8 MB | 12.5 MB |

官方那兩塊是整個 5×5 度網格（含福建沿岸、琉球），我們只有台灣。
**小不是缺資料，是沒有多餘的資料** —— 但也因此，圖磚的邊界之外真的沒有路網，
騎士如果人在境外，路線會算不出來而不是繞遠。

建圖還會順手產出 `E110_N10.rd5` 之類的小塊（南沙、東沙落在裡面），
那些**不出貨**：一塊圖磚存在會讓 App 以為那裡有路網。

## lookups.dat 動過一個字

`app/src/main/assets/brouter/lookups.dat` 在 way 區段的**最後**多了一行
`scooter:hook_turn;0000000001 yes`。附加在最後是刻意的 —— 前面每個標籤的
索引都不動，所以**官方圖磚仍然解得開**，只是這個標籤永遠不會出現。
那正是「自建的壞掉就退回官方」這條退路仍然成立的原因。

版本號沒有動。改既有標籤或插在中間才要動版本，而那會讓官方圖磚解出錯誤的標籤。
