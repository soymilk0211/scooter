# 規則模型是「預設值 + 例外」，不是逐路口建檔

台北市交工處公布的三份開放資料，名稱本身就是「**例外**開放機車直接左轉路口」與「**例外**實施兩段式左轉管制清冊」—— 法規的實際結構是：三車道以上預設待轉、二車道預設可直接左轉，再個案核准例外。三份 CSV 合計不到 11 KB，全市例外僅約一兩百筆。

因此規則不逐路口儲存，而是**由車道數與路型推導預設值，再以例外清單覆寫**。這讓覆蓋率一開始就接近全國，社群只需回報例外，回報需求量降低一到兩個數量級，冷啟動問題大幅緩解。

預設規則本身是**可更新的資料**，每個行政區一組 —— 各縣市邏輯不同，且政策會變（二車道開放直接左轉是近年才修訂的）。

## Consequences

- 預設值算錯會造成大範圍錯誤，不像逐筆資料錯一筆只影響一個路口。
- 規則需附信心等級；低信心時退回中性播報（「請依現場標誌指示」）而非猜測。
- 規則含有系統無法判定的生效時段條件時，同樣退回中性播報。
