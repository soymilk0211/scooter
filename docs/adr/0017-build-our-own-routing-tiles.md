# 自建路網圖磚，因為回報要改變得了路線

[ADR-0016](0016-brouter-instead-of-valhalla-on-device.md) 選了 BRouter，
並用官方每週重建的圖磚跑通了路線計算。**但那條路有一個硬邊界**：
BRouter 的 profile 讀的是 OSM 標籤，讀不到我們的資料庫。所以

- OSM 已有的轉向限制（臺北 1,204 條）→ 路線會遵守
- **騎士回報的禁止左轉 → 路線完全看不到**
- 待轉成本（[ADR-0012](0012-hook-turn-is-a-cost-not-a-restriction.md)）→ 同樣看不到

我原本建議「先只播報，等回報量大了再說」。**使用者否決了，而且否決得對**：

> 要讓導航變聰明應該是要所有方面都考慮到，導航還是需要繞過禁止左轉

**回報如果改變不了路線，「越來越聰明」就只是一句話。** 一個騎士停在路口
按下「禁止左轉」，他的合理期待是下一個人不會被導來這裡 ——
而不是下一個人被導來這裡、然後聽到一句「前方禁止左轉」。

因此：**自建 rd5 圖磚，建圖時把我們的規則注入成自訂標籤。**
BRouter 的建圖工具就在我們已經下載的 `-all.jar` 裡，而我們本來就有一條
Python 管線在把 OSM 與政府資料組成種子庫 —— 這是那條管線多長一個分支，
不是一套新東西。

## 這同時解決了三件事

1. **騎士回報的禁止左轉**進得了路線計算，成為真正的轉向限制。
2. **待轉成本**可以用 `turncost`／節點 `initialcost` 表達（ADR-0012 的原意）。
3. **`prohibited_segments.way_ids` 終於有用途** —— 它是注入時的鍵。
   （先前我把它寫成「事後驗證的鍵」，那是錯的：BRouter 不帶 OSM way 編號。）

## 它解決不了路名

**路名放不進去，而且不是工具鏈的問題是格式的問題。** `lookups.dat` 是一份
標籤字典，圖磚裡存的是「第幾號標籤、第幾號值」的索引對，
這只對值可以列舉的標籤成立。路名幾乎每條都不同，字典會跟資料一樣大 ——
那正是圖磚只有 11–21 MB 的原因。整份 `lookups.dat` 裡 `name` 的條目數是 **0**。

路名要走另一條路：我們的管線本來就在抓帶路名的道路幾何，
把「座標 + 方位角 → 路名」建成索引放進種子庫即可（決策檔案 D5/D7）。
自建圖磚讓這件事變順手 —— 同一趟 OSM 處理的產物。

## Consequences

- **ADR-0008 的「每月固定成本 NT$0」不再成立。** 33 MB 的圖磚要自己 host
  並定期重建，靜態檔案的流量不是零。候選與取捨見決策檔案 D8。
- **建圖是一條要維護的管線。** OSM 每天在變而機車規則不會，
  所以重建頻率不必跟官方一樣每週（決策檔案 D9）。
- **失去了「用官方圖磚就好」這個退路的簡單性。** 官方圖磚仍然可以當
  fallback ——自建的壞掉時退回官方，代價只是回報不影響路線，
  而那正好是這個決定之前的狀態。這個 fallback 值得保留。
- **注入的規則要能被關掉。** 一筆錯誤的禁止左轉被烘進圖磚之後，
  修正要等下一次重建。所以注入的門檻要比播報高 ——
  ADR-0013 說禁止左轉一律進審核佇列，這裡是那條規定真正的理由。
