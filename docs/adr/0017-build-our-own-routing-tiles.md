# 自建路網圖磚，因為回報要改變得了路線

[ADR-0016](0016-brouter-instead-of-valhalla-on-device.md) 選了 BRouter，
並用官方每週重建的圖磚跑通了路線計算。**但那條路有一個硬邊界**：
BRouter 的 profile 讀的是 OSM 標籤，讀不到我們的資料庫。所以

- OSM 已有的轉向限制（臺北 1,204 條）→ 路線會遵守
- **騎士回報的禁止左轉 → 路線完全看不到**
- 待轉成本（[ADR-0012](0012-hook-turn-is-a-cost-not-a-restriction.md)）→ 同樣看不到

我原本建議「先只播報，等回報量大了再說」。**使用者否決了，而且否決得對**：

> 要讓導航變聰明應該是要所有方面都考慮到，導航還是需要繞過禁止左轉

**回報如果改變不了路線，「越來越聰明」就只是一句話。** 一個騎士停在路口
按下「禁止左轉」，他的合理期待是下一個人不會被導來這裡 ——
而不是下一個人被導來這裡、然後聽到一句「前方禁止左轉」。

因此：**自建 rd5 圖磚，建圖時把我們的規則注入成自訂標籤。**
BRouter 的建圖工具就在我們已經下載的 `-all.jar` 裡，而我們本來就有一條
Python 管線在把 OSM 與政府資料組成種子庫 —— 這是那條管線多長一個分支，
不是一套新東西。

## 這同時解決了三件事

1. **騎士回報的禁止左轉**進得了路線計算，成為真正的轉向限制。
2. **待轉成本**可以用 `turncost`／節點 `initialcost` 表達（ADR-0012 的原意）。
3. **`prohibited_segments.way_ids` 終於有用途** —— 它是注入時的鍵。
   （先前我把它寫成「事後驗證的鍵」，那是錯的：BRouter 不帶 OSM way 編號。）

## 蓋出來之後：第一件成立，第二件只成立一半（2026-08-18）

管線在 `pipeline/tiles/`。三步都是 BRouter 官方的建圖工具原封不動地跑，
注入全部發生在它們看到資料之前 —— **一行 BRouter 的程式都沒有改**，
因為「我們改過它的內部類別」這種相依性會在它發新版那天才爆炸。

**禁止左轉成立，而且是量得出來的。** 合成一條 `type=restriction` 關聯
（from way / via node / to way）餵進去，建圖工具讀到的轉向限制從 2,590 變成
2,591，台北車站到市府的路線從 6,398 公尺變成 6,627 公尺 —— 那個左轉被禁掉了，
路線繞過去。同一次建置的其他三組起訖**一個位元都沒變**，注入是外科手術式的。

**待轉沒有成立，而且卡住的地方跟圖磚無關。** 標籤進得了圖磚（實測：拿
`costfactor` 擋那條 link，路線確實改變），profile 也寫好了 `turncost`，
但 `scooter-tw.brf` 從 `car-fast.brf` 繼承了 `---model:btools.router.KinematicModel`，
而 **`KinematicPath` 整支沒有呼叫過 `getTurncost()`**（`StdPath` 才有）。
實測：`turncost` 設成 2000 跑台北到台中、76 個轉彎，成本一個位數都沒有變。

**而且不能只把 `---model:` 那行刪掉。** car-fast 的 `costfactor` 對一般道路是
**0**（它是疊在動力學成本上的加碼，不是距離乘數），改走 `StdPath` 之後距離變成
免費 —— 實測成本歸零、有一組起訖直接算不出來。要讓待轉成本生效，得連
`costfactor` 一起改寫，那是換掉整個成本模型，見決策檔案 D10。

所以待轉的注入**預設關著**（`--hook-turns` 才會做）。機制留著、測過了，
換成本模型那天打開即可，不必重建圖磚以外的東西。

### 就算生效了，待轉的精度也有上限

這一點是 BRouter 的結構決定的，寫下來免得下一個人以為是 bug：
`turncost` 是 **way 層**的變數（進入那條 link 時求值，再乘上 `1 - cos 轉角`），
**不是 (從哪來, 往哪去) 的函數**。所以把待轉標在左轉的離開臂上時，
**對向來車的右轉會吃到同一筆成本**。

比較過的替代方案更差：節點層的 `initialcost` 連直行一起罰，而直行是大路口
最常見的動作 —— 四叉路口十二種動線裡只有一種該罰，用節點層等於罰十二種。
離開臂那個做法罰兩種。所以選它。

## 它解決不了路名

**路名放不進去，而且不是工具鏈的問題是格式的問題。** `lookups.dat` 是一份
標籤字典，圖磚裡存的是「第幾號標籤、第幾號值」的索引對，
這只對值可以列舉的標籤成立。路名幾乎每條都不同，字典會跟資料一樣大 ——
那正是圖磚只有 11–21 MB 的原因。整份 `lookups.dat` 裡 `name` 的條目數是 **0**。

路名要走另一條路：我們的管線本來就在抓帶路名的道路幾何，
把「座標 + 方位角 → 路名」建成索引放進種子庫即可（決策檔案 D5/D7）。
自建圖磚讓這件事變順手 —— 同一趟 OSM 處理的產物。

## Consequences

- **ADR-0008 的「每月固定成本 NT$0」不再成立。** 圖磚要自己 host 並定期重建，
  靜態檔案的流量不是零。放 GitHub Releases（決策檔案 D8）。
  實際大小**比預期小**：自建 20.3 MB 對官方 33.5 MB —— 官方那兩塊是整個
  5×5 度網格（含福建沿岸、琉球），我們只有台灣。
- **高程資料不需要。** `PosUnifier` 吃一個 SRTM 目錄，我們給它一個不存在的路徑。
  `scooter-tw.brf` 一個 `uphillcost`／`downhillcost` 都沒指定，高程只會改變回報
  的時間與能量、不會改變路線 —— 實測自建（無高程）與官方（有高程）跑同一組
  起訖，距離一模一樣。這省掉一整套 SRTM 的取得與前處理。
- **`lookups.dat` 多了一行，而且是加在 way 區段的最後。** 附加在最後，
  前面每個標籤的索引都不動，所以**官方圖磚仍然解得開** —— 那正是下面那條
  fallback 仍然成立的原因。插在中間或改既有標籤都會讓官方圖磚解出錯誤的標籤。
- **建圖是一條要維護的管線。** OSM 每天在變而機車規則不會，
  所以重建頻率不必跟官方一樣每週（決策檔案 D9）。
- **失去了「用官方圖磚就好」這個退路的簡單性。** 官方圖磚仍然可以當
  fallback ——自建的壞掉時退回官方，代價只是回報不影響路線，
  而那正好是這個決定之前的狀態。這個 fallback 值得保留。
- **注入的規則要能被關掉。** 一筆錯誤的禁止左轉被烘進圖磚之後，
  修正要等下一次重建。所以注入的門檻要比播報高 ——
  ADR-0013 說禁止左轉一律進審核佇列，這裡是那條規定真正的理由。
  實作上這是一個 `status IN (OFFICIAL, VERIFIED)` 的條件：回報一進資料庫是
  PENDING，那些不進圖磚。
- **切 way 會動到既有的轉向限制，所以有一條安全規則。**
  待轉的注入要把離開臂第一段切成獨立的 way，而被既有 `type=restriction` 關聯
  引用到的 way 一切開，那條關聯就會指到半條路，BRouter 可能解成**反方向**的
  轉向限制。所以那種 way 一律不切，並且寫進報告 —— 拿一個軟成本去換一條真的
  禁止左轉出錯，不划算。自我測試的兩筆裡就有一筆被這條規則擋掉。
