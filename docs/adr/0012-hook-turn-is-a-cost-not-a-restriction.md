# 待轉是路線成本，不是轉向限制

ADR-0011 讓路線引擎開始遵守 OSM 的轉向限制關聯。接下來會有一個很自然、
而且會壞掉的念頭：**待轉路口對機車來說不就是「不能左轉」嗎？那把它也編成
`no_left_turn` 不就好了。**

不行。`no_left_turn` 的語意是「這個轉彎不存在」，路線引擎會**繞開整個路口**，
去找別的路左轉。而待轉路口是**可以左轉的**，只是要多等一個號誌週期。
把待轉編成禁轉，會讓騎士被導去繞三個街廓，去完成一個他原地等 40 秒就能做完的左轉。
更糟的是這個錯誤不會被抱怨成錯誤 —— 路線看起來是合法的，只是莫名其妙地繞遠，
而騎士無從得知原因。

所以：

- **禁止左轉 → 轉向限制。** 那個轉彎在圖上不存在。
- **待轉 → 轉向成本。** 那個轉彎存在，只是貴一點（一個號誌週期，臺北市常見
  的路口約 30–90 秒）。

同一個道理反過來也成立，而且更容易忽略：**「直接左轉」的價值不是抵達，是省時。**
騎士到得了目的地與否兩者相同，差別只在待轉多花的那一個週期。這決定了警示的
語氣 —— 播錯「直接左轉」會讓騎士違規吃單，播錯「待轉」只是慢一點。
不對稱在這裡，不在能不能到。

## Consequences

- 待轉規則要以**成本加乘**的形式餵給路線引擎，不能走 `access` 或 `restriction`
  那條路。Valhalla 的做法是路口轉向的懲罰值，不是禁止。
- **沒有建檔的路口不加任何成本**，路線與現在一樣。這讓建檔覆蓋率提高時，
  路線品質是**漸進**變好的，不會在某個門檻突然改變行為。
- 「避開待轉」不做成使用者可調的選項。它聽起來像貼心功能，實際上是把
  「我們也不確定哪些路口要待轉」這個事實包裝成偏好設定。
- 只有一種情況待轉真的等於禁止：**該路口沒有待轉區**（例如左轉出口是單行道逆向）。
  那時它本來就是 `no_left_turn`，由路線層處理，不是待轉的特例。
