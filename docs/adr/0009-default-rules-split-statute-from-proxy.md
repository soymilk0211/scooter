# 預設規則分兩層：法源歸法源，某個縣市的實務歸實務

多數路口沒有個別建檔，規則來自預設規則（ADR-0004）。臺北市那份是「二車道原則上
直接左轉、三車道以上原則上待轉」，寫在 `build_seed.py` 的一行註解裡。

**讀起來像法條的推導，但它不是。** 道路交通安全規則 §99 的「三快車道以上」
**限定單行道**；一般道路強制兩段式左轉的觸發條件是**內側車道禁行機車**或現場標誌。
那份車道數規則是**臺北市交通局的行政實務**，在臺北實務上幾乎都對（三車道以上內側
幾乎都禁行機車），但**那是巧合不是推導**。路線圖原本要把它複製到每一個新增的縣市，
那會把一個在臺北剛好成立的巧合，變成二十二份錯誤。

而正確的法源**推導不出任何東西**：觸發條件需要車道級的禁行機車資料，
OSM 的 `motorcycle:lanes` 在實測的一千一百多段台中主要幹道上覆蓋率是 **0%**，
路段級的 `motorcycle` 只有 9% 且已知不可信。

因此分兩層寫進 `default_rules.py`：**法源層**記下什麼才是法律上的真觸發條件
（目前無法推導，但它讓下一層的性質不會被誤讀），**代理層**放各縣市各自的實務規則，
以**縣市碼**為鍵（行政區代碼的前 5 碼，資料裡本來就有 —— 用縣市名當鍵要一路處理
臺／台與各種簡寫，而那正是 `field_checks.json` 不用路名當鍵的同一個理由）。

## Consequences

- **沒有登錄的縣市不產生預設規則**，只有個別建檔的路口有規則。沉默是刻意的：
  一個沒查證過的縣市，猜出來的預設會在幾千個路口同時播錯。這與「單一路口缺資料時
  偏向待轉」不衝突 —— 那是縣市已登錄時的保守，不是憑空生出一個縣市的規則。
- 加一個縣市要做的事只有一件：在 `CITY_DEFAULTS` 加一筆並寫明 `basis`。
  結構不必再改。
- **不進資料庫**。App 的播報不會因為依據是市府實務還是法條而不同，那是建檔期的
  資訊，不是騎乘期的。因此不需要 schema 遷移 —— 而遷移目前是在第一次定位更新時
  才跑的，也就是騎乘途中。
- 固定測速**不跟著這條縣市邊界走**，一律全國寫入。它自帶座標、速限與拍攝方向，
  不依賴任何推導，所以沒查證過的縣市也只會得到正確的警示。
  兩種資料的失敗方式不同，邊界就不該共用。
